# AWSセキュリティ・暗号化学習記録

## 学習概要
- 暗号化キー管理サービス (KMS, CloudHSM) の違い
- SSL/TLS証明書管理 (ACM)

## 暗号化サービスの使い分け
AWSでデータを暗号化する際の「鍵（キー）」を管理するサービス。

### AWS KMS (Key Management Service)
- **役割**: AWSマネージドな暗号化キー管理サービス。
- **特徴**:
    - **AWSサービスとの統合**: S3, EBS, RDSなどの暗号化スイッチをONにするだけで、裏側で勝手にKMSが使われる。これが最大に便利。
    - **共有（マルチテナント）**: 裏側のハードウェア（HSM）はAWSが管理し、複数のユーザーで共有している（論理的には分離されている）。
    - **管理**: キーの作成やローテーションは簡単。権限はIAMポリシーで制御。
- **使い所**: 一般的なWebアプリや、AWSサービス上のデータを暗号化したい場合の**第一選択肢**。

### AWS CloudHSM
- **役割**: クラウド上で「専用のハードウェア（HSM）」を独占して使うサービス。
- **特徴**:
    - **専有（シングルテナント）**: あなた専用の物理デバイスが確保される。
    - **完全制御**: AWSの管理者ですらキーの中身を見ることはできない。ユーザーが完全にコントロールする。
    - **コンプライアンス**: 「FIPS 140-2 レベル3」などの厳しいセキュリティ基準や、特定の暗号化ライブラリ（PKCS#11など）への対応が必要な場合に使う。
    - **管理**: 難しい。HSMのクラスター管理やバックアップなどを自分で行う必要がある。
- **使い所**: 金融機関など、法規制で「暗号化キーを自社専用のハードウェアで管理しなければならない」という要件がある場合。

## KMSとCloudHSMの比較表
| 特徴 | KMS | CloudHSM |
| :--- | :--- | :--- |
| **ハードウェア** | 共有 (マルチテナント) | **専有** (シングルテナント) |
| **管理の手間** | **楽** (AWSにお任せ) | 大変 (自分で管理) |
| **AWS統合** | **最強** (チェック入れるだけ) | 難しい (カスタム実装が必要) |
| **コスト** | 安い | 高い (時間課金) |
| **主な用途** | 一般的な暗号化 | 厳しいコンプライアンス要件 |

## AWS Certificate Manager (ACM)
- **役割**: SSL/TLSサーバー証明書の発行・更新・管理を行うサービス。
- **【SAA試験対策ポイント】**:
    1.  **無料**: ACMで発行したパブリック証明書は無料。
    2.  **自動更新**: ACMで発行した証明書は、有効期限が切れる前に**勝手に自動更新**してくれる（運用が神レベルに楽になる）。
    3.  **使えない場所**: **EC2には直接インストールできない**。これが最大のひっかけ問題。
        - ⭕️ **使える**: ALB, CloudFront, API Gateway などのマネージドサービス。
        - ❌ **使えない**: EC2の中のApacheやNginxに直接置くこと。
    4.  **検証方法**: 証明書を作る時、「本当にドメインの持ち主？」という確認が必要。
        - **DNS検証**: Route53にレコードを追加するだけ（推奨・自動更新できる）。
        - **Eメール検証**: メールで承認する（面倒・自動更新できない場合がある）。

## 現時点での理解レベル
- 基本はKMSを使えばOK。S3やEBSの暗号化はKMSが裏で動いている。
- CloudHSMは「どうしても専用の機械が必要」という厳しい業界（金融など）向けのプロ仕様。
- ACMは「証明書をタダで配ってくれて、更新も勝手にやってくれる神サービス」。ただしEC2には直接入れられない（必ずALBなどを噛ませる必要がある）。
