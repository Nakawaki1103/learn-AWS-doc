# AWSネットワーク応用学習記録 (SAA対策)

## 学習概要
- Route 53のルーティングポリシー
- VPCエンドポイントの種類
- ハイブリッド接続 (VPN, Direct Connect, Transit Gateway)
- CloudFrontの高度な機能

## Amazon Route 53 (DNS)
- **役割**: ドメインネームシステム (DNS) サービス。ドメイン登録とルーティングを行う。
- **ルーティングポリシー（頻出）**:
    - **シンプル**: 普通のDNS。重み付けなし。
    - **加重 (Weighted)**: Aサーバーに80%、Bサーバーに20%のようにトラフィックを分散（ABテストなど）。
    - **レイテンシー**: ユーザーにとって遅延が最も少ない（近い）リージョンへ誘導。
    - **フェイルオーバー**: メインが死んだら（ヘルスチェック失敗）、自動でバックアップサイト（S3静的サイトなど）へ切り替え。
    - **地理的近接性**: 地図上の距離に基づいてルーティング。
    - **複数値回答**: 複数のIPアドレスを返して、クライアント側で選ばせる（簡易ロードバランス）。
- **エイリアスレコード**: AWSリソース（ALB, S3, CloudFrontなど）専用のレコード。CNAMEより高速で無料。ルートドメイン（`example.com`）にも使える。

## VPCエンドポイント
- **役割**: VPCの中から、インターネットに出ずにAWSサービス（S3など）にアクセスするための抜け道。セキュリティ向上に必須。
- **2つの種類（超重要）**:
    1.  **ゲートウェイ型 (Gateway Endpoint)**:
        - 対象: **S3** と **DynamoDB** のみ。
        - 仕組み: ルートテーブルにルートを追加する。
        - 料金: **無料**。
    2.  **インターフェイス型 (Interface Endpoint / PrivateLink)**:
        - 対象: 上記以外のほとんどのサービス（EC2 API, SNS, CloudWatchなど）。
        - 仕組み: サブネット内にENI（プライベートIP）を作る。
        - 料金: **有料**（時間課金＋通信量）。

## ハイブリッド接続・ハブ
- **AWS Site-to-Site VPN**:
    - インターネット経由でオンプレミスとVPCを暗号化接続。
    - 安価だが、通信品質はネット回線依存。
- **AWS Direct Connect (DX)**:
    - **専用線**でオンプレミスとAWSを直結。
    - 安定、高速、高セキュリティだが、高価で納期がかかる。
- **AWS Transit Gateway**:
    - **ネットワークのハブ**。
    - 多数のVPCやVPN、Direct Connectを中央で束ねて相互接続する。
    - 「VPCピアリングが複雑になりすぎた時」の解決策。

## Amazon CloudFront (CDN)
- **OAI (Origin Access Identity) / OAC (Origin Access Control)**:
    - S3をオリジンにする際、「CloudFront経由のアクセスだけ許可し、S3への直接アクセスは禁止する」ための設定。
- **Lambda@Edge / CloudFront Functions**:
    - エッジロケーションでコードを実行し、リクエスト/レスポンスを加工する。

## 現時点での理解レベル
- Route 53は単なるDNSではなく、フェイルオーバーなどの高度なルーティングができる。
- VPCエンドポイントは「S3/DynamoDBはゲートウェイ型（無料）」と覚えるのが鉄則。
- Transit Gatewayは「VPCが増えすぎた時の整理役」。
