# AWS SAA試験対策 重要単語集

SAA (Solutions Architect Associate) 試験を受ける上で、意味を即答できるようにしておきたい重要単語まとめ。

## パフォーマンス・指標
- **スループット (Throughput)**
    - **意味**: 単位時間あたりの処理量。「土管の太さ」。
    - **例**: 1秒間に何MB転送できるか、何件処理できるか。
- **レイテンシー (Latency)**
    - **意味**: 反応速度、遅延。「待ち時間」。
    - **例**: クリックしてから画面が出るまでの時間。低いほど良い（速い）。
- **IOPS (Input/Output Per Second)**
    - **意味**: 1秒あたりのディスク読み書き回数。
    - **重要**: データベース（RDS, EBS）の性能を決める最重要指標。Provisioned IOPS (io1/io2) で数値を指定できる。

## ネットワーク・ロケーション
- **リージョン (Region)**
    - **意味**: 地理的に離れたAWSの拠点（東京、バージニアなど）。
- **アベイラビリティーゾーン (AZ)**
    - **意味**: リージョン内にある独立したデータセンター群。互いに数km離れており、停電や災害の影響を隔離できる。
- **エッジロケーション**
    - **意味**: CloudFrontなどが使うキャッシュ配信拠点。リージョンよりも数が圧倒的に多い。
- **CIDR (Classless Inter-Domain Routing)**
    - **意味**: IPアドレスの範囲を表す表記法（例: `10.0.0.0/16`）。
    - **コツ**: `/`の後の数字が小さいほど範囲が広い（`/16`は約6.5万個、`/24`は256個）。
- **ステートフル (Stateful)**
    - **意味**: 状態（文脈）を覚えていること。
    - **例**: **セキュリティグループ**。「行き」を許可すれば「帰り」も自動許可（顔パス）。
- **ステートレス (Stateless)**
    - **意味**: 状態を覚えないこと。
    - **例**: **ネットワークACL**。「行き」と「帰り」を別々に許可が必要（毎回チェック）。

## 高可用性・耐障害性
- **単一障害点 (SPOF: Single Point of Failure)**
    - **意味**: そこが壊れたらシステム全体が止まってしまう箇所。
    - **対策**: これを無くす（冗長化する）のが設計の基本。
- **フェイルオーバー (Failover)**
    - **意味**: メイン機が壊れたら、自動的に予備機に切り替わること（RDS Multi-AZなど）。
- **マルチAZ (Multi-AZ)**
    - **意味**: 複数のAZにリソースを配置すること。
    - **効果**: 1つのデータセンターが火事になってもシステムが止まらない（高可用性）。
- **スケーラビリティ (Scalability)**
    - **意味**: 負荷に応じてシステムを拡大・縮小できる能力。
    - **スケールアップ**: サーバーのスペック（CPU/メモリ）を上げる。再起動が必要なことが多い。
    - **スケールアウト**: サーバーの台数を増やす。クラウド向きで、無停止で拡張しやすい。

## デプロイ・運用手法
- **ブルー/グリーンデプロイ**
    - **意味**: 新旧2つの環境を用意し、トラフィックを切り替える手法。
    - **メリット**: ダウンタイムゼロ、切り戻し（ロールバック）が瞬時に可能。
- **カナリアリリース**
    - **意味**: 一部のユーザー（10%など）だけに新バージョンを公開し、様子を見てから全体に広げる手法。
    - **由来**: 毒ガス検知のための「炭鉱のカナリア」。
- **イミュータブル (Immutable)**
    - **意味**: 「不変」。一度作ったサーバーは変更しない。
    - **運用**: 修正時はパッチを当てず、新しいサーバーを作り直して入れ替える考え方。
- **疎結合 (Loose Coupling)**
    - **意味**: システム同士の依存度を下げること。
    - **実装**: SQSなどを間に挟むことで、片方が落ちてももう片方が生き残れるようにする。対義語は「密結合」。

## データ・整合性
- **結果整合性 (Eventual Consistency)**
    - **意味**: 「そのうちデータが一致する」。
    - **特徴**: 書き込み直後は古いデータが見えるかもしれないが、高速。S3（上書き時）やDynamoDB（デフォルト）など。
- **強い整合性 (Strong Consistency)**
    - **意味**: 「書き込んだら即座に最新が見える」。
    - **特徴**: データの正確性重視。RDSやDynamoDB（オプション指定時）。
- **ACID特性**
    - **意味**: トランザクション処理に求められる4つの性質（原子性、一貫性、独立性、永続性）。RDBが備えている。

## その他重要概念
- **マネージドサービス**
    - **意味**: AWSが運用管理（OSパッチ、バックアップ、障害対応等）を代行してくれるサービス。
    - **例**: RDS, Lambda, S3, DynamoDB。ユーザーはアプリ開発に集中できる。
- **サーバーレス**
    - **意味**: サーバーの存在を意識せずにコードや機能だけを実行できるモデル。
    - **例**: Lambda, Fargate, DynamoDB, S3。実際にはサーバーはあるが、管理しなくていい。
- **責任共有モデル**
    - **意味**: AWSとユーザーでセキュリティの責任範囲を分担する考え方。
    - **AWSの責任**: クラウド「の」セキュリティ（物理設備、ネットワークなど）。
    - **ユーザーの責任**: クラウド「における」セキュリティ（OSパッチ、データ暗号化、パスワード管理など）。
