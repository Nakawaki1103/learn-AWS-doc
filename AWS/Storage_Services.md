# AWSストレージサービス学習記録 (SAA対策)

## 学習概要
- S3のストレージクラスと機能
- EBSのボリュームタイプ
- EFS, FSx, Storage Gatewayの使い分け

## Amazon S3 (Simple Storage Service)
- **役割**: 容量無制限のオブジェクトストレージ。
- **ストレージクラス（頻出）**:
    - **Standard**: 標準。頻繁なアクセス。
    - **Intelligent-Tiering**: アクセスパターンに応じて自動で階層移動（コスト最適化）。
    - **Standard-IA (Infrequent Access)**: 低頻度アクセス。取り出し料金がかかるが保管料は安い。
    - **One Zone-IA**: 1つのAZのみに保存（安価だがAZ障害でデータロストのリスクあり）。
    - **Glacier**: アーカイブ用。取り出しに時間がかかる（数分〜数時間）。激安。
        - **Instant Retrieval**: すぐ取り出せるGlacier。
        - **Deep Archive**: 最も安い。取り出しに12時間以上かかることも。
- **機能**:
    - **ライフサイクルポリシー**: 作成から30日後にIAへ、1年後にGlacierへ移動、といった自動化。
    - **バージョニング**: 上書き・削除しても過去の状態に戻せる（誤削除対策）。
    - **クロスリージョンレプリケーション**: 別のリージョンに自動でバックアップ（DR対策）。
    - **署名付きURL**: 一時的に特定のユーザーだけにアクセスを許可するURLを発行。

## Amazon EBS (Elastic Block Store)
- **役割**: EC2にアタッチするブロックストレージ（HDD/SSD）。
- **ボリュームタイプ**:
    - **gp3 (汎用SSD)**: バランス型。IOPSとスループットを個別に設定可能。基本はこれ。
    - **io2 (プロビジョンドIOPS SSD)**: 超高性能。DBなど高いIOPSが必要な場合。高い。
    - **st1 (スループット最適化HDD)**: ビッグデータ、ログ処理など。シーケンシャルアクセスが得意。
    - **sc1 (Cold HDD)**: アクセス頻度の低いデータ用。安い。
- **機能**:
    - **スナップショット**: S3にバックアップを保存。
    - **マルチアタッチ**: io2のみ、複数のEC2から同時にマウント可能（特殊な用途）。

## ファイルストレージの使い分け
| サービス | プロトコル | 対象OS | 特徴 | 用途 |
| :--- | :--- | :--- | :--- | :--- |
| **EFS** | NFS | **Linux** | 自動拡張、複数EC2から同時アクセス可能。 | Webサーバーのコンテンツ共有、ホームディレクトリ |
| **FSx for Windows** | SMB | **Windows** | Windowsネイティブな共有フォルダ。AD連携。 | Windowsファイルサーバーの移行 |
| **FSx for Lustre** | - | Linux | 超高速。S3と連携可能。 | HPC、機械学習、動画処理 |

## Storage Gateway
- **役割**: オンプレミスとAWSのストレージを橋渡しするハイブリッドクラウドサービス。
- **種類**:
    1.  **ファイルゲートウェイ**: オンプレからNFS/SMBでアクセスすると、裏で**S3**に保存される。
    2.  **ボリュームゲートウェイ**: オンプレのデータのバックアップ（スナップショット）を**EBS**としてAWSに保存。
        - **キャッシュ型**: よく使うデータだけオンプレに置く。
        - **保管型**: 全データをオンプレに置き、バックアップだけAWSへ。
    3.  **テープゲートウェイ**: 物理的な磁気テープのバックアップを**Glacier**などに移行。

## 現時点での理解レベル
- S3はクラスの使い分け（特にGlacier系）とライフサイクルが重要。
- EBSはgp3が基本で、DBならio2。
- Linux共有ならEFS、Windows共有ならFSx。
- オンプレ連携ならStorage Gateway。
