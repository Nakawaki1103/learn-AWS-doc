# AWSサーバーレス・アプリ連携応用学習記録 (SAA対策)

## 学習概要
- Lambda, API Gatewayの機能詳細
- イベント駆動アーキテクチャ (SNS, SQS, EventBridge)
- ワークフロー管理 (Step Functions)
- ユーザー認証 (Cognito)

## AWS Lambda (FaaS)
- **制限**: 最大実行時間は**15分**。これを超える処理はAWS BatchやStep Functionsを使う。
- **レイヤー**: 共通のライブラリ（NumPyなど）をまとめて管理し、複数の関数で共有する機能。
- **同時実行数**: デフォルト1000。これを超えるとスロットリング（制限）される。

## Amazon API Gateway
- **役割**: APIの入り口（玄関）。認証、流量制限（スロットリング）、バージョン管理を行う。
- **種類**:
    - **REST API**: 高機能。WAFが使える。
    - **HTTP API**: シンプル、低コスト、高速。機能は限定的。
    - **WebSocket API**: リアルタイム双方向通信（チャットなど）。

## アプリケーション連携パターン
- **ファンアウト (Fan-out) パターン**:
    - **SNS + SQS** の組み合わせ。
    - 1つのメッセージ（SNS）を、複数のキュー（SQS）に同時にコピーして配信する。
    - 例：注文確定イベント → 「在庫管理キュー」と「配送処理キュー」と「メール通知キュー」に同時に送る。
- **Amazon EventBridge (旧 CloudWatch Events)**:
    - **イベントバス**。AWSサービスやSaaSアプリからのイベントを受け取り、ルールに基づいてターゲット（Lambdaなど）に振り分ける。
    - スケジュール実行（Cron）も可能。

## AWS Step Functions
- **役割**: 複数のAWSサービス（Lambdaなど）を組み合わせた**ワークフロー（処理の流れ）**を定義・実行する。
- **特徴**:
    - 状態遷移（ステートマシン）を可視化できる。
    - エラーハンドリング、リトライ、条件分岐が簡単。
    - **使い所**: 「Lambda Aの結果を見て、成功ならB、失敗ならCを実行」といった複雑なロジック。Lambdaの中でLambdaを呼ぶのはアンチパターンなので、Step Functionsを使う。

## Amazon Cognito
- **役割**: Web/モバイルアプリのユーザー認証・認可基盤。
- **2つのプール（超重要）**:
    1.  **ユーザープール (User Pool)**:
        - **「認証 (Authentication)」**を担当。
        - ユーザー名/パスワードの管理、サインアップ、ログイン画面の提供。
        - 結果として「JWTトークン」を発行する。
    2.  **IDプール (Identity Pool)**:
        - **「認可 (Authorization)」**を担当。
        - 認証されたユーザーに対し、一時的な**AWSクレデンシャル（IAMロール）**を渡す。
        - これにより、アプリから直接S3に写真をアップロードしたり、DynamoDBを読み書きしたりできる。

## 現時点での理解レベル
- Lambdaは15分制限があるため、長い処理はBatchかStep Functionsへ。
- ファンアウトパターン（SNS→SQS）は疎結合アーキテクチャの基本。
- Cognitoは「ユーザープール＝会員証発行」「IDプール＝合鍵渡し」という違い。
